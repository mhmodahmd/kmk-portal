# 05 — الصلاحيات

> الحالة: **مسودة للاعتماد** · آخر تحديث: 2026-11-14

## 1. المبدأ

الصلاحية = **الدور في الوحدة** + **نطاق البيانات**.

- لكل مستخدم دور مستقل في كل وحدة (جدول `UserRoles`). مثال: "موظف" في الحضور، و"محاسب" في العهد، ولا شيء في المالية.
- **المدير المباشر ليس دوراً** بل علاقة: من يكون `managerId` لموظفين يرى طلباتهم ويوافق عليها تلقائياً.
- **مدير النظام** (`isSuperAdmin`) يملك كل شيء، ويجب أن يبقى واحد نشط على الأقل.
- الوحدة غير المفعّلة أو التي لا يملك المستخدم فيها دوراً لا تظهر له إطلاقاً.
- كل الصلاحيات تُتحقق في الخادم.

## 2. نطاقات البيانات
| النطاق | المعنى |
|---|---|
| `self` | سجلاتي فقط |
| `team` | سجلاتي + من أنا مديرهم المباشر (وما تحتهم) |
| `all` | كل السجلات في الوحدة |

## 3. الأدوار لكل وحدة

### الحضور والانصراف
| الإجراء | موظف | مشاهد | الموارد البشرية |
|---|:-:|:-:|:-:|
| تسجيل دخول/انصراف | ✔ self | ✔ self | ✔ self |
| عرض السجل | self | all | all |
| حضور اليوم والتقارير | (team للمدير) | all | all |
| طلب تصحيح بصمة | ✔ | ✔ | ✔ |
| اعتماد التصحيح / تعديل يدوي | (team للمدير: اعتماد فقط) | ✖ | ✔ |
| إعدادات النطاق الجغرافي | ✖ | ✖ | ✔ |

### الموارد البشرية
| الإجراء | موظف | الموارد البشرية |
|---|:-:|:-:|
| ملفي الوظيفي | self (قراءة) | all |
| طلب إجازة / إضافي | ✔ | ✔ |
| موافقة المرحلة الأولى | (team للمدير) | ✔ |
| القرار النهائي، الأرصدة، الإنشاء نيابةً | ✖ | ✔ |
| دليل الموظفين والمستندات | ✖ | ✔ |
| الهيكل (أقسام، ورديات، عطل، أنواع إجازات) | ✖ | ✔ |
| إنهاء الخدمة | ✖ | ✔ |

### العهد والنثريات (كما في النظام الحالي)
| الإجراء | صاحب عهدة | محاسب |
|---|:-:|:-:|
| عرض العهد | self | all |
| إضافة/تعديل مصروف (والعهدة مفتوحة) | ✔ self | ملاحظة على البند |
| طلب نثرية، طلب إغلاق، طلب سند | ✔ | ✔ |
| فتح عهدة، اعتماد، رفض، اختيار التسوية | ✖ | ✔ |
| السندات: إصدار، اعتماد طلب، طباعة، PDF | طباعة سنداته | ✔ |
| تصحيح بند معتمد، حذف عهدة | ✖ | ✖ (مدير النظام فقط) |

### المهام
| الإجراء | عضو | مدير المهام |
|---|:-:|:-:|
| مهامي: إنشاء، تحديث الحالة، تعليق | ✔ | ✔ |
| إسناد مهمة لغيري | لفريقي (team) | all |
| رؤية المهام | ما أنا مسؤول عنه أو متابع له + team | all |
| المهام المتكررة، حذف المهام | ✖ | ✔ |
| **مهمة خاصة** (0.9.6): لا يراها إلا منشئها، ولا مدير المهام ولا مدير النظام؛ مسندة إليه بلا متابعين، تُنجز بلا مراجعة، ويحذفها هو | ✔ لمنشئها | ✔ لمنشئها (ولا يرى خاصة غيره) |
| ربط المهمة بعميل أو عهدة أو موظف | حسب أدواره في الوحدات الأخرى (`tsk.lookups.links`) | كذلك |

- كل مستخدم «عضو» تلقائياً (`defaultRole` في `MODULES`)، و«مدير المهام» يُسند يدوياً.
- «منجزة» من المسؤول على مهمة أسندها غيره تصبح «بانتظار مراجعة»، ويعتمدها من أسندها أو مدير المسؤول أو مدير المهام من صندوق الموافقات.
- من أسند المهمة أو مدير المسؤول يعدّلها ويلغيها؛ المسؤول يعدّل الوصف والقائمة الفرعية والمرفقات.

### العملاء
| الإجراء | مبيعات | محاسب | مدير مبيعات |
|---|:-:|:-:|:-:|
| العملاء والتواصل | العملاء المسندون لي | all (قراءة) | all |
| الفرص وعروض الأسعار | ما أملكه | ✖ | all |
| الدفعات (تسجيل وتعديل) | ✖ | ✔ | ✔ |
| إعادة إسناد العملاء، التقارير | ✖ | ✖ | ✔ |
| حذف عميل أو مشروع (`crm.client.remove`, `crm.project.remove`) | ✖ | ✖ | ✔ (ولا يُحذف عميل له مشاريع أو مشروع عليه دفعات) |

### المراسلات (0.9.7)
| الإجراء | موظف مراسلات | مدير المراسلات |
|---|:-:|:-:|
| تسجيل خطاب وارد أو صادر، تعديله، إرفاق ملفات، تسجيل رد مرتبط بالأصل | ✔ | ✔ |
| رؤية الخطابات (`cor.list`, `cor.get`) | ما سجّله أو أُحيل إليه | all |
| تغيير الحالة (مُرسل، تم الرد، أرشفة) والإحالة إلى مسؤول آخر | على ما يراه | all |
| إعادة خطاب من الأرشيف، أو إرجاع صادر إلى مسودة | ✖ | ✔ |
| الحذف النهائي (`cor.remove`؛ لا يُحذف خطاب له ردود) | ✖ | ✔ |
| تصنيفات المراسلات (`cor.category.save` / `cor.category.move`) | ✖ | ✔ |
| التقرير (`cor.report`) | ضمن ما يراه | all |
| قوائم الربط في الحوار (`cor.lookups.links`): العملاء والمشاريع للجميع، العهد للمحاسب (أو عهد الموظف نفسه)، الموظفون للموارد البشرية (أو فريقه ونفسه)، المهام ما يراه المستخدم في وحدة المهام | حسب أدواره | كذلك |

- الدور يُسند من «المستخدمون والأدوار» (لا دور افتراضي). مدير النظام يملك كل شيء.
- الإشعارات: من يُحال إليه خطاب أو يُسند إليه عند التسجيل، وتذكير بموعد الرد (قبل يومين وعند التأخر) لمن سجّل الخطاب والمسؤول عنه.
- قسم «المراسلات» في صفحة العميل أو المشروع يظهر لمن له دور في المراسلات فقط، ويعرض ما يراه منها.

| الإجراء | مشاهد | محاسب | مدير مالي |
|---|:-:|:-:|:-:|
| النظرة العامة والتقارير | ✔ | ✔ | ✔ |
| تسجيل حركات، فواتير، مقبوضات | ✖ | ✔ | ✔ |
| إلغاء حركة أو فاتورة (بسبب) | ✖ | ✖ | ✔ |

## 4. صلاحيات النظام (مدير النظام فقط)
المستخدمون والأدوار · تفعيل الوحدات · إعدادات الشركة · المشاريع · سجل العمليات · النسخ والأرشفة · الحذف النهائي.

## 5. تحويل الأدوار الحالية
| النظام الحالي | الدور الحالي | في النظام الجديد |
|---|---|---|
| الحضور | `admin` | مدير النظام + الموارد البشرية |
| الحضور | `viewer` | الحضور: مشاهد |
| الحضور | `employee` | الحضور: موظف + الموارد البشرية: موظف |
| العهد | `admin` (سوبر أدمن) | مدير النظام + العهد: محاسب |
| العهد | `accountant` | العهد: محاسب |
| العهد | `employee` | العهد: صاحب عهدة |

## 6. مثال
**أحمد** مصمم في قسم التصميم، ومديره المباشر **سارة**:
- الحضور: موظف · الموارد البشرية: موظف · العهد: صاحب عهدة · المهام: عضو
- يرى: بصمته، إجازاته، عهدته، مهامه.
- **سارة** بالأدوار نفسها، لكنها مديرة أحمد، فترى تلقائياً حضور أحمد وطلبات إجازته ومهامه، وتوافق عليها كمرحلة أولى.
